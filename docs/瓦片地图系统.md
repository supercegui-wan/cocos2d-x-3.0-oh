## 概述

### TMX 格式简介

TMX（Tile Map XML）是由 [Tiled Map Editor](http://www.mapeditor.org) 生成的开放标准瓦片地图格式。cocos2d-x 3.0-oh 内建了完整的 TMX 解析与渲染支持，能够直接加载 `.tmx` 文件并构建可交互的瓦片地图场景。

TMX 格式的核心概念：

| 概念 | 说明 |
|------|------|
| **地图（Map）** | 顶层容器，定义地图尺寸、瓦片尺寸、方向（正交/六边形/等距）和全局属性 |
| **图层（Layer）** | 瓦片数据层，每个图层包含一个二维瓦片索引数组，每个索引指向 Tileset 中的具体瓦片 |
| **Tileset（瓦片集）** | 瓦片纹理图集的元数据描述，包含纹理图像路径、瓦片尺寸、间距、边距、FirstGID 等 |
| **对象组（Object Group）** | 自由放置的游戏对象集合，每个对象有位置、尺寸、类型和自定义属性，用于碰撞区域、出生点、NPC 位置等 |
| **属性（Properties）** | 键值对形式的自定义数据，可附加到地图、图层、对象组、对象和单个瓦片上 |

### 支持的 TMX 特性

- **三种地图方向**：正交（Orthogonal）、六边形（Hexagonal）、等距（Isometric）
- **对象组与对象**：支持矩形、椭圆、多边形、折线等几何对象类型
- **多层级属性**：地图级、图层级、对象组级、对象级、瓦片级属性全覆盖
- **瓦片标记（Tile Flags）**：支持水平翻转、垂直翻转、对角翻转
- **数据编码**：支持 XML 原始格式、Base64、Gzip、Zlib 压缩编码
- **运行时操作**：支持运行时增删瓦片、修改瓦片 GID、旋转/缩放/着色/透明度控制

### 不支持的特性

- 每个图层仅支持一个 Tileset
- 不支持 TMX 内嵌图像（Embedded Images）
- 仅支持 XML 格式的 TMX 文件（不支持 JSON 格式的 TMX）

### 核心类关系

```text
TMXTiledMap (Node)                    ← 地图容器，解析并渲染 TMX
├── TMXLayer (SpriteBatchNode) × N    ← 每个可见图层创建一个 TMXLayer 实例
│   └── Sprite (tile) × M             ← 每个瓦片按需创建为 Sprite
├── TMXObjectGroup (Ref) × P          ← 每个对象组
│   └── ValueMap (object) × Q         ← 每个对象以 ValueMap 表示
└── 解析依赖
    ├── TMXMapInfo (Ref + SAXDelegator)  ← 解析器，将 TMX 文件转为结构化数据
    │   ├── TMXLayerInfo × N          ← 图层元数据
    │   └── TMXTilesetInfo × M        ← Tileset 元数据
    └── SAXParser                      ← 底层 XML SAX 解析器
```

## 1. TMXTiledMap 瓦片地图

**文件**：`cocos/2d/CCTMXTiledMap.h`

**继承链**：`Ref` → `Node` → `TMXTiledMap`

### 1.1 架构设计

`TMXTiledMap` 是整个瓦片地图系统的根节点。它接收一个 `.tmx` 文件或 TMX 格式的 XML 字符串，通过 `TMXMapInfo` 解析器将 XML 转换为结构化数据，随后为每个可见图层创建 `TMXLayer` 子节点，为每个对象组创建 `TMXObjectGroup` 实例。

**内部构建流程**：

```text
create(tmxFile) / createWithXML(tmxString, resourcePath)
  → TMXMapInfo::create(tmxFile)  ← 解析 TMX XML，生成 TMXLayerInfo / TMXTilesetInfo / TMXObjectGroup 列表
  → buildWithMapInfo(mapInfo)
      → 遍历 TMXMapInfo 中的图层信息
          → tilesetForLayer()  ← 为每个图层匹配对应的 Tileset
          → parseLayer()       ← 创建 TMXLayer 实例并添加到当前节点
      → 复制 TMXMapInfo 中的对象组到 _objectGroups
      → 复制 TMXMapInfo 中的属性和瓦片属性到 _properties / _tileProperties
```

**技术说明**：
- 每个 TMX 图层对应一个 `TMXLayer`（`SpriteBatchNode` 子类），以子节点形式添加到 `TMXTiledMap`
- 如果图层在 Tiled 中标记为不可见（`visible="false"`），则该图层不会被创建，降低内存和渲染开销
- 图层的 Tag 按创建顺序从 0 开始递增，可通过 `getChildByTag(tag)` 获取
- 瓦片纹理通过 `TextureCache` 加载，利用纹理缓存避免重复加载
- 瓦片默认关闭抗锯齿（aliased），适合像素风格瓦片地图

### 1.2 方向类型

```cpp
enum {
    TMXOrientationOrtho,  // 正交方向（标准俯视网格）
    TMXOrientationHex,    // 六边形方向（六角网格）
    TMXOrientationIso,    // 等距方向（2.5D 斜视）
};
```

| 方向 | 枚举值 | 典型使用场景 | 坐标计算特点 |
|------|--------|-------------|-------------|
| 正交（Ortho） | `TMXOrientationOrtho` | 俯视 RPG、平台游戏、策略游戏 | 行列轴与屏幕轴平行，`pos = tileCoord * tileSize` |
| 等距（Iso） | `TMXOrientationIso` | 2.5D 城市建设、RTS 游戏 | 瓦片呈菱形，屏幕坐标需做倾斜变换 |
| 六边形（Hex） | `TMXOrientationHex` | 六角战棋、策略游戏 | 六边形排列，奇偶行/列偏移 |

### 1.8 特性与限制

**特性**：
- 每个瓦片是独立的 `Sprite`，支持旋转、移动、缩放、着色（`setColor`）、透明度（`setOpacity`）
- 瓦片按需创建（Lazy Instantiation）：仅在调用 `layer->getTileAt(pos)` 时实例化为 Sprite，在此之前只以 `uint32_t` GID 形式存储，节省内存
- 运行时支持动态增删瓦片（`setTileGID` / `removeTileAt`）
- 每个瓦片有唯一 Tag 和唯一 Z 值（左上角 Z=1，右下角 Z=最大）
- 每个图层默认关闭抗锯齿
- 瓦片 anchorPoint 为 (0, 0)，TMXTiledMap 自身的 anchorPoint 也为 (0, 0)

**限制**：
- 每个图层仅支持一个 Tileset
- 不支持内嵌图像
- 仅支持 XML 格式的 TMX

## 2. TMXLayer 瓦片图层

**文件**：`cocos/2d/CCTMXLayer.h`

**继承链**：`Ref` → `Node` → `SpriteBatchNode` → `TMXLayer`

### 2.1 概述

`TMXLayer` 代表 TMX 地图中的一个图层，继承自 `SpriteBatchNode`。默认情况下，瓦片通过 `TextureAtlas` 批量渲染。当在运行时修改某个瓦片（如调用 `getTileAt()` 获取 Sprite 并修改其属性）时，该瓦片才会被实例化为独立的 `Sprite` 对象。

**继承 SpriteBatchNode 的优势**：
- 所有同图层瓦片共享同一纹理图集，使用一次 Draw Call 即可完成整个图层的渲染
- 瓦片（作为 Sprite）可以使用 Sprite 的全部 API 进行旋转、缩放、移动、着色、透明度等操作

### 2.2 创建方式

```cpp
static TMXLayer* create(TMXTilesetInfo* tilesetInfo, TMXLayerInfo* layerInfo, TMXMapInfo* mapInfo);

// 初始化方法
bool initWithTilesetInfo(TMXTilesetInfo* tilesetInfo, TMXLayerInfo* layerInfo, TMXMapInfo* mapInfo);
```

一般不由用户直接调用，而是由 `TMXTiledMap::parseLayer()` 内部创建。

### 2.3 瓦片获取与设置

```cpp
// 获取指定瓦片坐标处的 Sprite（自动创建 Sprite 实例）
Sprite* getTileAt(const Point& tileCoordinate);

// 获取指定瓦片坐标处的 GID 和瓦片标记（不创建 Sprite）
uint32_t getTileGIDAt(const Point& tileCoordinate, TMXTileFlags* flags = nullptr);

// 设置指定瓦片坐标处的 GID（替换或放置瓦片）
void setTileGID(uint32_t gid, const Point& tileCoordinate);

// 设置指定瓦片坐标处的 GID 并指定瓦片标记
void setTileGID(uint32_t gid, const Point& tileCoordinate, TMXTileFlags flags);

// 移除指定瓦片坐标处的瓦片
void removeTileAt(const Point& tileCoordinate);

// 【已废弃】获取瓦片 Sprite
CC_DEPRECATED_ATTRIBUTE Sprite* tileAt(const Point& tileCoordinate);

// 【已废弃】获取瓦片 GID
CC_DEPRECATED_ATTRIBUTE uint32_t tileGIDAt(const Point& tileCoordinate, TMXTileFlags* flags = nullptr);
```

**GID 说明**：
- GID（Global ID）是瓦片的全局标识符，在 Tiled Editor 中对应 Tileset Manager 的编号 + 1
- GID 为 0 表示该位置无瓦片
- GID 的高 3 位用于存储瓦片标记（翻转信息），低 29 位为实际 GID

**瓦片标记（Tile Flags）**：

```cpp
typedef enum TMXTileFlags_ {
    kTMXTileHorizontalFlag  = 0x80000000,  // 水平翻转
    kTMXTileVerticalFlag    = 0x40000000,  // 垂直翻转
    kTMXTileDiagonalFlag    = 0x20000000,  // 对角翻转
    kTMXFlipedAll           = (kTMXTileHorizontalFlag | kTMXTileVerticalFlag | kTMXTileDiagonalFlag),
    kTMXFlippedMask         = ~(kTMXFlipedAll)  // 用于提取实际 GID
} TMXTileFlags;
```

### 2.4 坐标转换

```cpp
// 将瓦片坐标转换为像素坐标（返回该瓦片在图层中的像素位置）
Point getPositionAt(const Point& tileCoordinate);

// 【已废弃】
CC_DEPRECATED_ATTRIBUTE Point positionAt(const Point& tileCoordinate);
```

坐标转换的行为取决于地图方向：
- **正交（Ortho）**：`pixelPos = tileCoord * tileSize`
- **等距（Iso）**：内部调用 `getPositionForIsoAt()`，按菱形倾斜计算
- **六边形（Hex）**：内部调用 `getPositionForHexAt()`，按六边形排列计算

### 2.6 内部实现

**关键内部成员**：

| 成员 | 类型 | 说明 |
|------|------|------|
| `_layerName` | `std::string` | 图层名称 |
| `_layerSize` | `Size` | 图层尺寸（瓦片数） |
| `_mapTileSize` | `Size` | 地图瓦片尺寸（像素） |
| `_tiles` | `uint32_t*` | 瓦片 GID 数组，长度为 `_layerSize.width * _layerSize.height` |
| `_tileSet` | `TMXTilesetInfo*` | 图层关联的 Tileset 信息 |
| `_layerOrientation` | `int` | 图层方向 |
| `_properties` | `ValueMap` | 图层属性字典 |
| `_opacity` | `unsigned char` | 图层不透明度（0-255） |
| `_reusedTile` | `Sprite*` | 复用的瓦片 Sprite（优化用） |
| `_useAutomaticVertexZ` | `bool` | 是否使用自动 VertexZ |
| `_vertexZvalue` | `int` | 手动 VertexZ 值 |
| `_atlasIndexArray` | `ccCArray*` | 图集索引数组（优化用） |

**特殊图层属性**：

| 属性名 | 值类型 | 说明 |
|--------|--------|------|
| `cc_vertexz` | `int` 或 `"automatic"` | 设置图层的 OpenGL Vertex Z。整数值直接作为所有瓦片的 VertexZ；`"automatic"` 启用自动 VertexZ 计算 |
| `cc_alpha_func` | `float` | 设置 Alpha 测试的阈值，默认 0。启用了自动 VertexZ 的图层在绘制前会启用 `GL_ALPHA_TEST`，绘制后关闭 |

**与 SpriteBatchNode 的交互约束**：
- `TMXLayer` 不支持手动 `addChild(Sprite)` 添加自定义精灵，应使用 `setTileGID()` 操作瓦片
- 覆盖了 `addChild(Node*, int, int)` 和 `removeChild(Node*, bool)` 方法

**优化方法**：

```cpp
// 释放瓦片位置映射表（释放后无法再调用 getTileGIDAt()）
void releaseMap();

// 创建瓦片
void setupTiles();
```

## 4. TMXXMLParser 解析器

**文件**：`cocos/2d/CCTMXXMLParser.h`

### 4.1 概述

TMXXMLParser 模块是 TMX 文件格式的底层解析器，负责将 `.tmx` 或 `.tsx` XML 文件解析为结构化的元数据对象。解析器基于 SAX（Simple API for XML）事件驱动模型，通过 `SAXParser` 实现流式解析，避免将整个 XML 文档加载到内存中。

**注意**：`TMXMapInfo`、`TMXLayerInfo`、`TMXTilesetInfo` 是内部解析类，用户通常不直接使用它们，而是通过 `TMXTiledMap::create()` 间接使用。

### 4.2 TMXMapInfo

**文件**：`cocos/2d/CCTMXXMLParser.h`

```cpp
// 根据 GID 计算该瓦片在纹理图集中的矩形区域

```

**GID 到纹理坐标的映射**：

`getRectForGID(gid)` 的计算逻辑：
1. 从 `gid` 中减去 `_firstGid`，得到该 Tileset 内的局部索引
2. 计算行号 = 局部索引 / 每行瓦片数
3. 计算列号 = 局部索引 % 每行瓦片数
4. 纹理坐标 X = `_margin + 列号 × (_tileSize.width + _spacing)`
5. 纹理坐标 Y = `_margin + 行号 × (_tileSize.height + _spacing)`
6. 尺寸 = `_tileSize`

### 4.5 解析流程

```text
TMXMapInfo::initWithTMXFile(tmxFile)
  → internalInit(tmxFileName, resourcePath)
  → parseXMLFile(tmxFileName)
      → SAXParser 读取 XML
          → startElement()  ← 处理每个 XML 开始标签
              ├── <map>       → 解析 orientation, width, height, tilewidth, tileheight
              ├── <tileset>   → 创建 TMXTilesetInfo，解析 firstgid, name, tilewidth, tileheight, spacing, margin
              │   └── <image> → 解析 source, width, height
              ├── <layer>     → 创建 TMXLayerInfo，解析 name, width, height, visible, opacity
              │   └── <data>  → 解析 encoding, compression，解码 tile GID 数据
              ├── <objectgroup> → 创建 TMXObjectGroup，解析 name, offsetx, offsety
              │   └── <object>  → 创建 ValueMap，解析 name, type, x, y, width, height, gid
              ├── <properties>  → 根据 parentElement 解析属性到对应层级
              │   └── <property> → 解析 name, value, type
              └── <tile>        → 解析 id，设置 parentGID
                  └── <properties> → 解析瓦片属性到 _tileProperties[GID]
          → endElement()    ← 处理每个 XML 结束标签
          → textHandler()   ← 收集文本内容（如 <data> 内的 Base64 编码瓦片数据）
  → 返回完整的 TMXMapInfo 对象
```

```cpp
        CCLOG("错误：无法加载地图文件");
        return;

    Size tileSize = map->getTileSize();

                }
            }
        }
    }

    // 处理对象组
    auto objGroup = map->getObjectGroup("collisions");
    if (objGroup) {
        ValueVector& objects = objGroup->getObjects();
        for (auto& objVal : objects) {
            ValueMap& obj = objVal.asValueMap();

            float y = obj["y"].asFloat();
            float w = obj["width"].asFloat();
            float h = obj["height"].asFloat();

            Point points[] = {
                Point(0, 0), Point(w, 0), Point(w, h), Point(0, h)
            };
            rect->drawPoly(points, 4, true, Color4F(1, 0, 0, 0.5f));
            rect->setPosition(Point(x, y));
            this->addChild(rect);
        }
    }
}
```

## 7. 坐标系统

### 7.1 瓦片坐标与像素坐标

瓦片地图涉及两套坐标系统：

| 坐标系统 | 说明 | 原点 | 轴方向 |
|----------|------|------|--------|
| **瓦片坐标** | 以瓦片为单位的网格坐标 | 左上角 (0, 0) | X 向右，Y 向下 |
| **像素坐标** | 屏幕像素坐标 | 地图左下角（cocos2d-x 坐标系） | X 向右，Y 向上 |

**坐标转换**：

```cpp
// 瓦片坐标 → 像素坐标
Point pixelPos = layer->getPositionAt(tileCoord);

// 像素坐标 → 瓦片坐标（需根据方向手动计算）
// 正交方向：tileX = pixelX / tileSize.width, tileY = pixelY / tileSize.height
```

### 7.2 正交方向（Orthogonal）坐标

```text
瓦片坐标系统（左上角原点）：
  (0,0)  (1,0)  (2,0)  ...
  (0,1)  (1,1)  (2,1)  ...
  (0,2)  (1,2)  (2,2)  ...

像素坐标转换：
  pixelX = tileX * tileSize.width
  pixelY = (mapHeight - tileY - 1) * tileSize.height  // Y 轴翻转以适配 cocos2d-x 坐标系
```

### 7.3 等距方向（Isometric）坐标

等距瓦片呈菱形，屏幕坐标计算方式：

```text
像素坐标转换：
  pixelX = (tileX - tileY) * tileSize.width / 2
  pixelY = (tileX + tileY) * tileSize.height / 2
```

在 `TMXLayer` 内部通过 `getPositionForIsoAt()` 方法实现。

### 7.4 六边形方向（Hexagonal）坐标

六边形方向的坐标计算取决于 Tiled 的 stagger 设置（`staggeraxis` 和 `staggerindex`），在 `TMXLayer` 内部通过 `getPositionForHexAt()` 方法实现。

### 7.5 坐标注意事项

1. **TMXTiledMap 的 anchorPoint 为 (0, 0)**，这意味着地图按左下角对齐
2. 每个瓦片的 **anchorPoint 也为 (0, 0)**，瓦片 Sprite 按其左下角定位
3. **Y 轴方向**：TMX 格式的 Y 轴向下（左上角原点），cocos2d-x 的 Y 轴向上（左下角原点），引擎内部会自动处理翻转
4. 对象组中的对象坐标（`x`, `y`）是 TMX 格式的像素坐标，使用前需确认是否需要进行 Y 轴翻转

## 8. 性能优化建议

### 8.1 图层管理

| 策略 | 说明 |
|------|------|
| 关闭不可见图层 | 在 Tiled 中将不需要显示或交互的图层标记为不可见，引擎不会为其创建 TMXLayer 节点，节省内存和 Draw Call |
| 合并静态图层 | 将不会在运行时修改的多个静态图层在 Tiled 中合并为一个图层，减少 TMXLayer 实例数 |
| 合理设置图层数量 | 每个 TMXLayer 需要至少一次 Draw Call，避免创建过多仅有少量瓦片的图层 |

### 8.2 瓦片操作

| 策略 | 说明 |
|------|------|
| 避免频繁调用 `getTileAt()` | 每次调用会创建 Sprite 实例，如果仅需读取 GID 值，使用 `getTileGIDAt()` 代替 |
| 调用 `releaseMap()` 释放索引 | 如果运行时不再需要查询瓦片 GID（只做渲染），调用 `releaseMap()` 释放内部瓦片位置映射表 |
| 批量操作瓦片时使用 `setTileGID()` | 直接设置 GID 比先获取 Sprite 再修改属性更高效 |
| 避免每帧大量修改瓦片 | 大量瓦片修改会触发 Sprite 创建或纹理切换，增加渲染开销 |

### 8.3 纹理管理

| 策略 | 说明 |
|------|------|
| 使用合理的瓦片图集尺寸 | Tileset 纹理图集不宜过大或过小，建议 1024×1024 或 2048×2048 |
| 减少图集数量 | 同一场景尽量使用同一个 Tileset，减少纹理切换。注意每个图层只能有一个 Tileset |
| 利用 TextureCache | 相同 Tileset 纹理只加载一次，被 `TextureCache` 缓存。多个地图共享相同 Tileset 时不会重复加载 |

### 8.4 渲染优化

| 策略 | 说明 |
|------|------|
| 利用 SpriteBatchNode 批量渲染 | 每个 TMXLayer 继承自 SpriteBatchNode，同一图层瓦片默认使用一次 Draw Call，性能优于逐个 Sprite 渲染 |
| 避免过多修改瓦片导致 Sprite 化 | 未修改的瓦片通过 TextureAtlas 批量渲染；一旦调用 `getTileAt()` 修改瓦片，该瓦片变为独立 Sprite，增加渲染开销 |
| 控制 VertexZ 使用 | 开启 `cc_vertexz=automatic` 会启用 `GL_ALPHA_TEST`，增加渲染开销。仅在需要深度排序时启用 |
| 地图尺寸分区加载 | 对于超大地图，考虑将地图拆分为多个 TMX 文件，按需加载可见区域 |

### 8.5 内存优化

| 策略 | 说明 |
|------|------|
| 及时释放不需要的地图 | 场景切换时，移除地图节点并确保没有外部引用持有 TMXLayer 或 TMXObjectGroup |
| 注意 `_tiles` 数组内存 | 每个 TMXLayer 的 `_tiles` 数组大小为 `layerSize.width × layerSize.height × sizeof(uint32_t)`，大地图会占用较多内存 |

- 确保 `.tmx` 文件和对应的纹理图像文件在编译时被正确复制到资源目录

### 9.2 坐标与定位

- `TMXTiledMap` 的 `anchorPoint` 为 (0, 0)，地图左下角对齐到父节点的 (0, 0) 位置
- 每个瓦片的 `anchorPoint` 为 (0, 0)，瓦片左下角对齐到计算出的像素位置
- 对象组中的对象坐标（`x`, `y`）是 TMX 格式的像素坐标，Y 轴方向与 cocos2d-x 相反，需要翻转
- 六边形和等距地图的坐标计算较复杂，建议使用 `getPositionAt()` 获取像素坐标，不宜手动计算

### 9.3 对象组数据

- 对象组中的对象以 `ValueMap` 形式存储，访问时需使用正确的键名和类型
- 对象没有 `rotation`、`visible` 等属性，这些在 Tiled 中设置但不会导出到 TMX
- 多边形和折线对象包含 `polygonPoints` 或 `polylinePoints` 键，值为 `ValueVector` 的坐标点数组

### 9.4 瓦片 GID 与翻转

- GID 为 0 表示该位置无瓦片
- 设置瓦片时注意 GID 范围，超出 Tileset 范围的 GID 会导致渲染异常
- 使用 `kTMXFlippedMask` 掩码提取实际 GID：`actualGID = gid & kTMXFlippedMask`
- 翻转标记仅在渲染时生效，`getTileGIDAt()` 返回的 GID 包含翻转标记位

### 9.5 生命周期

- `TMXLayer` 和 `TMXObjectGroup` 的生命周期由 `TMXTiledMap` 管理
- 从地图节点移除图层子节点时，图层对应的瓦片数据也会被释放
- 不要手动释放 `TMXTilesetInfo`、`TMXLayerInfo` 等内部解析对象，它们由 `TMXMapInfo` 管理

### 9.6 编码与压缩

- Tiled 默认使用 XML 格式存储瓦片数据，可读性强但文件较大
- 推荐在 Tiled 中开启 Base64 + Zlib 压缩，可显著减小 `.tmx` 文件体积
- 引擎支持 Base64、Gzip、Zlib 压缩编码，无需额外配置

### 9.7 跨平台注意事项

- 不同平台的文件路径分隔符不同，使用 `FileUtils` 提供的路径方法而非硬编码
- 纹理图像格式需兼容目标平台（PNG 为通用推荐格式）
- 大型 Tileset 纹理需考虑移动端 GPU 纹理尺寸限制（通常 2048×2048 或 4096×4096）
