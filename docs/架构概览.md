## 1. 项目概述

cocos2d-x 3.0-oh 是基于 cocos2d-x 3.0 的 OpenHarmony (OHOS) 适配版本，是一个跨平台 2D 游戏引擎框架，支持 Win32、Android、iOS、macOS、Linux 和 OpenHarmony 等多个平台。

| 属性 | 值 |
|------|-----|
| 版本 | 3.0 |
| 语言 | C++ (C++11)、Lua、JavaScript |
| 图形 API | OpenGL ES 2.0（移动端）/ OpenGL 2.1（桌面端） |
| 构建系统 | CMake 2.8+、VS2012+、Xcode 4.6+、Python 2.7.5 |

## 5. 核心设计模式

### 5.1 单例模式

引擎中全局唯一的运行态管理器均采用单例模式，通过 `static Type* getInstance()` 获取实例。典型单例包括：

`CCDirector`、`CCScheduler`、`CCActionManager`、`CCEventDispatcher`、`CCTextureCache`、`CCShaderCache`、`CCSpriteFrameCache`、`CCAnimationCache`、`CCFileUtils`、`CCUserDefault`、`CCConfiguration`、`CCApplication` 等。

### 5.2 引用计数 + 自动释放池

`CCRef` 是所有引擎对象的基类，提供 `retain()` / `release()` / `autorelease()` 机制。`AutoreleasePool` 管理每帧结束时批量释放，避免手动管理生命周期导致的泄漏或野指针。

```cpp
// 典型用法：工厂方法返回的对象已 autorelease，调用方 retain 后持有
auto sprite = CCSprite::create("image.png");  // 已 autorelease
this->addChild(sprite);                       // addChild 内部 retain
// 帧末 AutoreleasePool 清理时，sprite 因引用计数 > 0 不会被释放
```

### 5.3 工厂方法 + 两阶段初始化

对象创建采用 `static Type* create()` 工厂方法 + `virtual bool init()` 两阶段初始化，配合 `CREATE_FUNC` 宏简化声明。

```cpp
// CREATE_FUNC 宏展开等价于：
static Type* create() {
    Type* pRet = new Type();
    if (pRet && pRet->init()) {
        pRet->autorelease();
        return pRet;
    }
    delete pRet;
    return nullptr;
}
```

### 5.4 场景图 + 访问者模式

`CCNode` 构成树形结构，`visit()` 方法递归遍历子节点完成渲染。每个节点在 `visit()` 中执行：变换矩阵计算 → 自身绘制 → 子节点递归 → 绘制后处理。

### 5.5 动作-目标模式

`CCAction` 作用于 `CCNode` 目标，通过 `CCActionManager` 统一调度。动作支持组合、序列、并行动画和缓动函数，与目标节点解耦。

### 5.6 组件模式

`CCComponent` 组件系统支持动态添加/移除组件，允许在不修改节点类的前提下扩展行为，遵循组合优于继承原则。

### 5.7 事件监听器模式（v3.0 新架构）

v3.0 引入 `EventListener` + `EventDispatcher` 替代旧的 `TouchDispatcher` 和 `KeypadDispatcher`。事件类型包括：

| 事件类型 | 监听器类 | 说明 |
|----------|----------|------|
| 触摸事件 | `EventListenerTouchOneByOne` / `EventListenerTouchAllAtOnce` | 单点/多点触摸 |
| 键盘事件 | `EventListenerKeyboard` | 物理键盘按键 |
| 鼠标事件 | `EventListenerMouse` | 桌面端鼠标移动/点击 |
| 加速度计 | `EventListenerAcceleration` | 设备加速度计读数 |
| 自定义事件 | `EventListenerCustom` | 用户自定义事件，通过事件名匹配 |

### 5.8 命令模式（渲染管线）

渲染管线采用命令模式：每个可绘制对象生成对应的 `RenderCommand`，`CCRenderer` 统一收集、排序和批量执行，优化 DrawCall。

## 6. 3.0 版本重大变更

与 cocos2d-x 2.x 相比，3.0 版本进行了以下重大调整：

| 序号 | 变更项 | 说明 |
|------|--------|------|
| 1 | 命名空间 | 所有类使用 `cocos2d::` 命名空间，通过 `NS_CC_BEGIN` / `NS_CC_END` 宏定义 |
| 2 | CC 前缀移除 | 部分内部类型移除了 CC 前缀（如 `Rect`、`Size`、`Point`） |
| 3 | 事件系统重构 | 引入 `EventListener` / `EventDispatcher` 替代旧的 `CCTouchDispatcher` / `CCKeypadDispatcher` |
| 4 | 渲染管线重构 | 引入 `RenderCommand` 队列和 `CCRenderer`，实现命令排序和批量渲染 |
| 5 | 容器类型升级 | 引入 `CCVector` / `CCMap` 替代 `CCArray` / `CCDictionary`，旧容器移至 `deprecated/` |
| 6 | 统一值类型 | `CCValue` 变体类型替代 `CCBool` / `CCInteger` / `CCFloat` / `CCDouble` / `CCString` |
| 7 | autorelease 池 | 从 `NSAutoreleasePool` 迁移到 `AutoreleasePool` |
| 8 | OpenHarmony 适配 | 新增 OHOS（OpenHarmony）平台完整支持 |

## 7. 平台支持矩阵

| 平台 | 编译标识 | 图形 API | 工具链 |
|------|----------|----------|--------|
| Win32 | `CC_PLATFORM_WIN32` | OpenGL 2.1 | VS2012+ |
| Android | `CC_PLATFORM_ANDROID` | OpenGL ES 2.0 | NDK r16b+ |
| iOS | `CC_PLATFORM_IOS` | OpenGL ES 2.0 | Xcode 4.6+ |
| macOS | `CC_PLATFORM_MAC` | OpenGL 2.1 | Xcode 4.6+ |
| Linux | `CC_PLATFORM_LINUX` | OpenGL 2.1 | CMake + GCC |
| OpenHarmony | `CC_PLATFORM_OHOS` | OpenGL ES 2.0 | DevEco Studio |
| WinRT | `CC_PLATFORM_WINRT` | OpenGL ES 2.0 | VS2012+ |
| WP8 | `CC_PLATFORM_WP8` | OpenGL ES 2.0 | VS2012+ |

### 7.1 平台适配层结构

每个平台在 `cocos/2d/platform/` 和 `cocos/platform/` 下均有独立实现目录，通过编译宏 `CC_PLATFORM_*` 在编译期选择对应代码路径。平台适配主要覆盖以下抽象：

- **窗口与 GL 上下文**：`CCEGLView` / `GLView` 实现
- **文件系统**：`CCFileUtils` 平台特化（资源路径、可写路径）
- **图像处理**：`CCImage` 平台编解码
- **设备信息**：`CCDevice` 获取 DPI、语言、设备型号等
- **应用生命周期**：`CCApplication` 平台入口和事件循环
