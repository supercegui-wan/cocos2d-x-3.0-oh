## 8. 解决方案

### 8.1 Win32 预编译库恢复

**方案 A（推荐）**：从官方源重新下载预编译库
- GLFW 3.x: 从 `https://www.glfw.org/download.html` 下载 Win32 预编译包
- GLEW: 从 `https://glew.sourceforge.net/` 下载 Win32 二进制包
- libiconv: 从 MSYS2 或 GnuWin32 提取

**方案 B**：从源码编译
- 使用 CMake + MSVC 或 MinGW 从源码编译 glfw/glew/iconv

### 8.2 OHOS 工具链安装

1. 下载并安装 DevEco Studio（HarmonyOS 开发 IDE）
2. 通过 DevEco Studio 的 SDK Manager 下载 OHOS SDK 和 Native NDK
3. 配置 `OHOS_NDK_HOME` 环境变量指向 NDK 路径
4. 配置 CMake 交叉编译工具链文件

### 8.3 CMake 升级（推荐）

从 `https://cmake.org/download/` 下载 CMake 3.28+ 正式版，替换当前的 3.10.0-rc1。

### 踩坑 #1: 预编译库缺失 — Win32 平台完全无法编译

| 项目 | 内容 |
|------|------|
| **严重程度** | **阻塞级** |
| **现象** | CMake 配置时找不到 `glfw3.lib`、`glew32.lib`、`iconv.dll` 等预编译库，链接阶段报 LNK1181 错误 |
| **根因** | 原始预编译库文件被标记为 `.REMOVED.git-id`，本意是避免二进制文件进入 git 仓库，但导致库文件实际上不存在 |
| **解决方案** | 使用 MSYS2 的 mingw32 工具链安装所有缺失的预编译库，并用 `gendef` + `lib.exe` 从 DLL 生成 `.lib` 导入库 |
| **预防措施** | 1. 在 `docs/` 中保留完整的预编译库清单；2. 在 `CMakeLists.txt` 中添加清晰的库文件检查；3. 考虑使用 vcpkg 管理依赖 |

**恢复步骤**:
```powershell
# 在 MSYS2 mingw32 终端中安装 32 位预编译库
pacman -S mingw-w64-i686-glfw
pacman -S mingw-w64-i686-glew
pacman -S mingw-w64-i686-libiconv
pacman -S mingw-w64-i686-libjpeg-turbo
pacman -S mingw-w64-i686-libpng
pacman -S mingw-w64-i686-libtiff
pacman -S mingw-w64-i686-libwebp
pacman -S mingw-w64-i686-freetype
pacman -S mingw-w64-i686-curl

# 从 DLL 生成 .lib 导入库（以 glew32 为例）
gendef glew32.dll
lib /machine:x86 /def:glew32.def /out:glew32.lib
```

### 踩坑 #2: libwebsockets 编译错误 — LWS_LIBRARY_VERSION 宏定义

| 项目 | 内容 |
|------|------|
| **严重程度** | **编译阻断级** |

### 踩坑 #8: GetCurrentDirectoryW 导致非 exe 目录运行失败

|------|------|
| **严重程度** | **运行阻断级** |

| **根因** | [CCFileUtilsWin32.cpp](file:///g:/cocos2d-x-3.0-oh/cocos/2d/platform/win32/CCFileUtilsWin32.cpp#L58-L71) 中 `_checkPath()` 使用 `GetCurrentDirectoryW` 获取当前工作目录 (CWD) 作为资源根路径。当从项目根目录运行 exe 时，CWD = `g:/cocos2d-x-3.0-oh/`，而 Resources 实际在 `build/.../Debug/Resources/`，导致资源路径错误 |

            *lastSlash = L'\0';  // 去掉 exe 文件名，保留目录
        }

}

### 踩坑 #9: CreateFileW dwShareMode=0 导致并发字体加载失败

| 项目 | 内容 |
|------|------|
| **严重程度** | **运行错误级** |
| **现象** | MH-Game.exe 启动后日志大量重复：`Get data from file(fonts/arial.ttf) failed, error code is 32`（ERROR_SHARING_VIOLATION），字体无法加载，界面文字显示异常 |
| **根因** | [CCFileUtilsWin32.cpp](file:///g:/cocos2d-x-3.0-oh/cocos/2d/platform/win32/CCFileUtilsWin32.cpp#L157) 中 `CreateFileW` 使用 `dwShareMode = 0`（独占模式打开）。当多个 Label 同时加载 `fonts/arial.ttf` 时，第一个 CreateFile 以独占模式打开文件，后续并发的 CreateFile 调用因共享冲突失败，返回 ERROR_SHARING_VIOLATION (32) |
| **解决方案** | 将两处 `CreateFileW` 的 `dwShareMode` 从 `0` 改为 `FILE_SHARE_READ`，允许其他进程/线程同时读取同一文件。由于只是读取操作，不存在数据竞争 |
| **预防措施** | 1. 读取文件时始终使用 `FILE_SHARE_READ` 而非独占模式；2. 仅在写入文件时使用独占模式；3. 审查所有 Win32 API 文件操作中的共享模式参数 |

**修复代码** (`CCFileUtilsWin32.cpp` 第157行和第232行):
```cpp
// 错误写法（独占模式，并发读取会失败）
HANDLE fileHandle = ::CreateFileW(wszBuf, GENERIC_READ, 0, NULL, OPEN_EXISTING, NULL, NULL);

// 正确写法（允许共享读取）
HANDLE fileHandle = ::CreateFileW(wszBuf, GENERIC_READ, FILE_SHARE_READ, NULL, OPEN_EXISTING, NULL, NULL);
```
