# cocos2d-x 3.0-oh 其他2D节点 (Other 2D Nodes)

## 概述

本文档涵盖 cocos2d-x 3.0-oh 中除核心 Sprite/Scene/Layer 之外的重要 2D 节点类，包括高性能绘制、运动拖尾、模板裁剪、进度计时、离屏渲染、视差滚动、图集渲染和网格特效系统。

**文件位置**: `cocos/2d/`

**类层次结构**:
```
Ref
└── Node
    ├── DrawNode           — 高性能几何绘制
    ├── MotionStreak       — 运动拖尾效果
    ├── ClippingNode       — 基于模板缓冲的裁剪
    ├── ProgressTimer      — 进度计时器（扇形/条形）
    ├── RenderTexture      — 离屏渲染到纹理
    ├── ParallaxNode       — 视差滚动
    ├── AtlasNode          — 纹理图集渲染
    └── NodeGrid           — 网格特效容器
```

## 1. DrawNode — 高性能几何绘制节点

**文件**: `cocos/2d/CCDrawNode.h`，继承自 `Node`

### 1.1 概述

DrawNode 提供了高效的几何图元绘制能力，支持点、线段、多边形、三角形、贝塞尔曲线等。与旧的 `CCDrawingPrimitives` 相比，DrawNode 将所有绘制命令合并到**单批次**中渲染，避免了多次 OpenGL draw call，性能显著提升。

### 1.2 架构设计

```
DrawNode
  ├── _vao / _vbo        — OpenGL VAO/VBO 句柄
  ├── _buffer            — 顶点缓冲区 (V2F_C4B_T2F 数组)
  ├── _bufferCapacity    — 当前缓冲区容量
  ├── _bufferCount       — 当前缓冲区有效顶点数
  ├── _dirty             — 脏标记，标记是否需要重新上传 VBO
  ├── _blendFunc         — 混合模式
  └── _customCommand     — 自定义渲染命令（接入 Renderer）
```

**工作流程**:
1. 每次调用绘制方法（如 `drawDot`）时，将顶点数据追加到 `_buffer`；
2. 若缓冲区不足，`ensureCapacity()` 自动扩容（通常翻倍）；
3. 设置 `_dirty = true`；
4. 在 `onDraw()` 回调中检查 `_dirty`，将脏数据上传至 VBO，执行一次 `glDrawArrays` 完成所有图元渲染。

### 1.3 绘制方法

| 方法 | 说明 |
|------|------|
| `drawDot(pos, radius, color)` | 在指定位置绘制实心圆点 |
| `drawSegment(from, to, radius, color)` | 绘制带半径的线段（圆角线段） |
| `drawPolygon(verts, count, fillColor, borderWidth, borderColor)` | 绘制填充多边形（可选描边） |
| `drawTriangle(p1, p2, p3, color)` | 绘制实心三角形 |
| `drawCubicBezier(from, control1, control2, to, segments, color)` | 绘制三次贝塞尔曲线 |
| `drawQuadraticBezier(from, control, to, segments, color)` | 绘制二次贝塞尔曲线 |
| `clear()` | 清空所有绘制数据 |

**参数说明**:
- `pos` / `from` / `to` / `p1-p3`: `Point` 类型，节点本地坐标；
- `radius`: 半径（点）或线宽（线段），单位：点；
- `color`: `Color4F` 类型，RGBA 浮点颜色（每个分量 0.0~1.0）；
- `verts`: `Point*` 顶点数组指针；
- `count`: 顶点数量；
- `segments`: 贝塞尔曲线分段数，越大越平滑；
- `fillColor` / `borderColor`: 填充色和边框色；
- `borderWidth`: 边框宽度。

### 1.4 缓冲区管理

```cpp
// 确保缓冲区能容纳 count 个新顶点
void ensureCapacity(int count);

// 内部采用 V2F_C4B_T2F 顶点格式，每个顶点包含：
//   - 位置 (Vertex2F: x, y)
//   - 颜色 (Color4B: r, g, b, a)
//   - 纹理坐标 (Tex2F: u, v) — DrawNode 中纹理坐标用于技术实现，不做实际纹理采样
```

**扩容策略**: 初始容量为内部默认值，不足时按 2 倍扩容，避免频繁分配。

### 1.5 混合模式

```cpp
const BlendFunc& getBlendFunc() const;
void setBlendFunc(const BlendFunc &blendFunc);
```

默认使用 `{GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA}` 标准混合。

### 1.6 使用示例

```cpp
// 创建 DrawNode
auto drawNode = DrawNode::create();
this->addChild(drawNode, 10);

// 绘制红色圆点
drawNode->drawDot(Point(100, 200), 10.0f, Color4F(1.0f, 0.0f, 0.0f, 1.0f));

// 绘制蓝色线段
drawNode->drawSegment(Point(50, 50), Point(200, 200), 3.0f, Color4F(0.0f, 0.0f, 1.0f, 1.0f));

// 绘制填充多边形（绿色填充，白色边框）
Point verts[] = { Point(0,0), Point(50,0), Point(50,50), Point(0,50) };
drawNode->drawPolygon(verts, 4, Color4F(0,1,0,0.5f), 2.0f, Color4F(1,1,1,1));

// 绘制三次贝塞尔曲线
drawNode->drawCubicBezier(
    Point(10, 100),       // 起点
    Point(50, 200),       // 控制点1
    Point(200, 0),        // 控制点2
    Point(300, 100),      // 终点
    32,                   // 分段数
    Color4F(1, 1, 0, 1)   // 黄色
);

// 清空所有绘制内容
drawNode->clear();
```

## 2. MotionStreak — 运动拖尾

**文件**: `cocos/2d/CCMotionStreak.h`，继承自 `Node` + `TextureProtocol`

### 2.1 概述

MotionStreak 用于创建运动拖尾效果（如刀光剑影、光带尾迹等）。它通过记录节点在运动过程中的位置序列，并在这些位置之间绘制一条逐渐衰减的带状纹理来实现拖尾。

### 2.2 拖尾原理

```
时间维度 → 越新越亮，越旧越淡

Vertex 0 (最新位置) ──── 不透明度 = 1.0
  │
Vertex 1              ──── 不透明度 = 1.0 - fadeDelta
  │
Vertex 2              ──── 不透明度 = 1.0 - 2×fadeDelta
  │
  ...
  │
Vertex N (最旧位置)   ──── 不透明度 = 0（被移除）
```

**核心机制**:
1. 每帧 `update(delta)` 中检查节点新位置与上一个记录点的距离；
2. 距离超过 `_minSeg` 时，插入新顶点；
3. 所有顶点的透明度随时间递减（`_fadeDelta`），透明度降为 0 的顶点被移除；
4. `draw()` 中将所有顶点构建为三角形带（Triangle Strip）渲染。

### 2.3 创建方式

```cpp
// 方式1：使用纹理文件路径
static MotionStreak* create(
    float fade,                // 淡出时间（秒）
    float minSeg,              // 最小分段距离（点）
    float stroke,              // 拖尾宽度（点）
    const Color3B& color,      // 拖尾颜色
    const std::string& path    // 纹理文件路径
);

// 方式2：使用已有 Texture2D 对象
static MotionStreak* create(
    float fade,
    float minSeg,
    float stroke,
    const Color3B& color,
    Texture2D* texture
);
```

### 2.4 关键参数

| 参数 | 类型 | 说明 |
|------|------|------|
| `fade` | `float` | 淡出时间（秒），值越小拖尾越短 |
| `minSeg` | `float` | 最小分段距离，值越小拖尾越平滑（但顶点更多） |
| `stroke` | `float` | 拖尾宽度（点） |
| `color` | `Color3B` | 拖尾颜色（RGB） |
| `_maxPoints` | `unsigned int` | 最大顶点数（由 `fade / minSeg * 2` 估算） |
| `_nuPoints` | `unsigned int` | 当前有效顶点数 |
| `_pointVertexes` | `Point*` | 顶点位置数组 |
| `_pointState` | `float*` | 顶点透明度状态数组 |

### 2.5 快速模式

```cpp
bool isFastMode() const;
void setFastMode(bool bFastMode);
```

- **普通模式** (`fastMode = false`): 精确计算顶点位置，但每帧需要遍历所有顶点更新透明度；
- **快速模式** (`fastMode = true`): 使用近似算法，顶点添加更快但精度较低，适合对拖尾精度要求不高的场景。

### 2.6 位置管理

MotionStreak 重写了 `setPosition`/`getPosition` 系列方法，使用内部 `_positionR` 存储位置。当节点移动时，拖尾自动跟随。

### 2.7 其他方法

| 方法 | 说明 |
|------|------|
| `tintWithColor(Color3B)` | 重新着色 |
| `reset()` | 清除所有拖尾分段，重新开始 |
| `getTexture()` / `setTexture()` | 获取/设置拖尾纹理 |
| `getBlendFunc()` / `setBlendFunc()` | 获取/设置混合模式 |
| `getOpacity()` / `setOpacity()` | 获取/设置不透明度 |
| `isStartingPositionInitialized()` | 起始位置是否已初始化 |

### 2.8 使用示例

```cpp
// 创建运动拖尾：淡出0.5秒，最小分段3点，宽度20点，白色，使用纹理
auto streak = MotionStreak::create(0.5f, 3.0f, 20.0f, Color3B::WHITE, "streak.png");
this->addChild(streak);

// 将拖尾绑定到运动的精灵上
auto sprite = Sprite::create("sword.png");
this->addChild(sprite);

// 每帧更新拖尾位置
this->schedule([=](float dt) {
    // sprite 在别处移动...
    streak->setPosition(sprite->getPosition());
}, "move_streak");

// 启用快速模式（高性能场景）
streak->setFastMode(true);

// 重新着色
streak->tintWithColor(Color3B(255, 100, 0));  // 橙色

// 重置拖尾
streak->reset();
```

## 3. ClippingNode — 模板裁剪节点

**文件**: `cocos/2d/CCClippingNode.h`，继承自 `Node`

### 3.1 概述

ClippingNode 使用模板（Stencil）对其子节点进行裁剪。裁剪区域由模板节点的不透明像素决定，内容仅在模板可见区域中绘制。底层基于 OpenGL 的**模板缓冲（Stencil Buffer）**实现。

### 3.2 模板裁剪原理

```
                     ┌─────────────────┐
  剪裁区域（Stencil  │  ★ 模板形状 ★   │
  的可见像素）       │     ┌───┐       │
                     │     │内容│       │  ← 只有模板覆盖区域的内容可见
                     │     └───┘       │
                     │                 │
                     └─────────────────┘
```

### 3.3 Stencil Buffer 实现

**渲染流程** (visit 方法):

1. **`onBeforeVisit()`** — 保存当前 OpenGL 模板状态，启用模板测试，设置模板写入；
2. **绘制模板节点（Stencil）** — 只写入模板缓冲，不写入颜色缓冲；
3. **`onAfterDrawStencil()`** — 修改模板函数，根据 `_inverted` 决定保留或反转模板区域；
4. **绘制所有子节点（内容）** — 模板测试生效，只有通过测试的像素被绘制；
5. **`onAfterVisit()`** — 恢复之前保存的 OpenGL 模板状态；
6. **`drawFullScreenQuadClearStencil()`** — 绘制全屏四边形清除模板缓冲（避免影响后续节点）。

**状态保存/恢复字段**:
```cpp
GLboolean _currentStencilEnabled;        // 模板启用状态
GLuint    _currentStencilWriteMask;      // 模板写入掩码
GLenum    _currentStencilFunc;           // 模板函数
GLint     _currentStencilRef;            // 模板参考值
GLuint    _currentStencilValueMask;      // 模板值掩码
GLenum    _currentStencilFail;           // 模板失败操作
GLenum    _currentStencilPassDepthFail;  // 模板通过、深度失败操作
GLenum    _currentStencilPassDepthPass;  // 模板通过、深度通过操作
GLboolean _currentDepthWriteMask;        // 深度写入掩码
GLboolean _currentAlphaTestEnabled;      // Alpha 测试启用状态
GLenum    _currentAlphaTestFunc;         // Alpha 测试函数
GLclampf  _currentAlphaTestRef;          // Alpha 测试参考值
GLint     _mask_layer_le;               // 模板掩码层级
```

### 3.4 Alpha 阈值

```cpp
GLfloat getAlphaThreshold() const;
void setAlphaThreshold(GLfloat alphaThreshold);
```

- **默认值**: `1.0`（禁用 Alpha 测试，即模板节点的所有绘制像素都参与裁剪）；
- **取值范围**: `0.0 ~ 1.0`；
- 当设为 `< 1.0` 时，只有模板节点中 Alpha 值大于阈值的像素才参与裁剪；
- 可用于实现基于 Alpha 的软裁剪效果。

### 3.5 反转模式

```cpp
bool isInverted() const;
void setInverted(bool inverted);
```

- `inverted = false`（默认）: 内容在模板**内部**可见；
- `inverted = true`: 内容在模板**外部**可见（即反转裁剪区域）。

### 3.6 模板节点

```cpp
Node* getStencil() const;
void setStencil(Node *stencil);
```

- 模板节点会被 ClippingNode 自动 retain，其 parent 设置为 ClippingNode；
- 模板节点本身不会被绘制到颜色缓冲中；
- 模板节点可以是任意 Node 子类（Sprite、DrawNode 等），但建议使用不透明或半透明的简单形状。

### 3.7 生命周期回调

| 回调 | 时机 |
|------|------|
| `onEnter()` | 节点进入场景 |
| `onEnterTransitionDidFinish()` | 入场过渡完成 |
| `onExitTransitionDidStart()` | 出场过渡开始 |
| `onExit()` | 节点退出场景 |
| `onBeforeVisit()` | 访问子节点前（准备模板状态） |
| `onAfterDrawStencil()` | 模板绘制后（设置模板测试条件） |
| `onAfterVisit()` | 访问子节点后（恢复模板状态） |

### 3.8 使用示例

```cpp
// 1. 圆形裁剪（使用 DrawNode 作为模板）
auto clip = ClippingNode::create();

// 创建圆形模板
auto stencil = DrawNode::create();
stencil->drawDot(Point(0, 0), 80.0f, Color4F::WHITE);
clip->setStencil(stencil);

// 添加内容（一张大图，只显示圆形区域）
auto content = Sprite::create("large_image.png");
clip->addChild(content);
this->addChild(clip);

// 2. 反转裁剪（圆形外部可见）
clip->setInverted(true);

// 3. 使用 Alpha 阈值实现软裁剪
clip->setAlphaThreshold(0.5f);  // 模板像素 Alpha > 0.5 才裁剪

// 4. 使用 Sprite 作为模板实现不规则裁剪
auto stencilSprite = Sprite::create("star_mask.png");
clip->setStencil(stencilSprite);
```

## 4. ProgressTimer — 进度计时器

**文件**: `cocos/2d/CCProgressTimer.h`，继承自 `Node`

### 4.1 概述

ProgressTimer 根据百分比参数渲染一个 Sprite 的部分区域，实现进度条效果。支持两种类型：**扇形（RADIAL）**和**条形（BAR）**。

### 4.2 类型枚举

```cpp
enum class Type {
    RADIAL,   // 扇形（逆时针展开）
    BAR,      // 条形（水平或垂直展开）
};
```

### 4.3 核心属性

| 属性 | 类型 | 说明 |
|------|------|------|
| `_type` | `Type` | 进度类型：RADIAL 或 BAR |
| `_percentage` | `float` | 进度百分比，取值范围 0~100 |
| `_sprite` | `Sprite*` | 显示进度的精灵 |
| `_midpoint` | `Point` | 中点，控制进度起始位置 |
| `_barChangeRate` | `Point` | 条形变化率，控制 BAR 模式下的变化方向 |
| `_reverseDirection` | `bool` | 是否反转进度方向 |
| `_vertexData` | `V2F_C4B_T2F*` | 顶点数据数组 |
| `_vertexDataCount` | `int` | 顶点数据数量 |

### 4.4 RADIAL（扇形）类型

- 从精灵中心点出发，以扇形方式按百分比逆时针展示；
- 由 `_midpoint` 控制扇形的起始角度和中心位置；
- 内部通过 `updateRadial()` 计算扇形顶点数据。

**中点对 RADIAL 的影响**:
- `_midpoint` 定义了扇形的起始位置（归一化坐标，相对于精灵尺寸）；
- 默认 `(0.5, 0.5)` 即从中心开始，从左侧（9点钟方向）逆时针展开。

### 4.5 BAR（条形）类型

- 以条形方式展示进度，由 `_midpoint` 和 `_barChangeRate` 共同控制方向；
- 内部通过 `updateBar()` 计算条形顶点数据。

**中点与变化率对 BAR 的影响**:

| 期望效果 | `_midpoint` | `_barChangeRate` |
|----------|-------------|------------------|
| 从左到右展开 | `(0, y)` | `(1, 0)` |
| 从右到左展开 | `(1, y)` | `(1, 0)` |
| 从下到上展开 | `(x, 0)` | `(0, 1)` |
| 从上到下展开 | `(x, 1)` | `(0, 1)` |

- `_midpoint` 决定条形从哪一侧开始展开；
- `_barChangeRate` 决定变化沿哪个轴线（x=1 水平，y=1 垂直）；设为 `(0,0)` 时条形保持不变。

### 4.6 反转方向

```cpp
bool isReverseDirection();
void setReverseDirection(bool value);
```

- 反转后 RADIAL 变为顺时针展开，BAR 变为从另一侧展开。

### 4.7 内部工作流程

1. 调用 `setPercentage()` → 更新 `_percentage`；
2. 触发 `updateProgress()` → 根据 `_type` 调用 `updateRadial()` 或 `updateBar()`；
3. `updateRadial()` / `updateBar()` 计算并更新 `_vertexData`；
4. `draw()` 中通过 `CustomCommand` 回调 `onDraw()`，使用 `_vertexData` 渲染。

### 4.8 使用示例

```cpp
// 创建扇形进度条
auto sprite = Sprite::create("progress_circle.png");
auto timer = ProgressTimer::create(sprite);
timer->setType(ProgressTimer::Type::RADIAL);
timer->setPercentage(0.0f);
this->addChild(timer);

// 动画到100%
auto to = ProgressTo::create(2.0f, 100.0f);
timer->runAction(to);

// 创建从左到右的条形进度条
auto barTimer = ProgressTimer::create(Sprite::create("health_bar.png"));
barTimer->setType(ProgressTimer::Type::BAR);
barTimer->setMidpoint(Point(0, 0.5f));      // 从左开始
barTimer->setBarChangeRate(Point(1, 0));     // 水平变化
barTimer->setPercentage(50.0f);

// 反转进度方向
barTimer->setReverseDirection(true);  // 从右到左

// 退步效果
timer->setReverseProgress(true);  // 设置后 setPercentage(0) 会从100退到0
```

## 5. RenderTexture — 渲染纹理

**文件**: `cocos/2d/CCRenderTexture.h`，继承自 `Node`

### 5.1 概述

RenderTexture 实现离屏渲染（Off-screen Rendering），将任意 Node 的渲染结果捕获到一张纹理中。底层使用 OpenGL 的**帧缓冲对象（FBO）**实现。渲染结果可作为精灵（Sprite）显示、保存为图片文件，或用于后续渲染。

### 5.2 创建方式

```cpp
// 完整参数：宽度、高度、像素格式、深度模板格式
static RenderTexture* create(int w, int h, Texture2D::PixelFormat format, GLuint depthStencilFormat);

// 指定像素格式（深度模板使用默认值）
static RenderTexture* create(int w, int h, Texture2D::PixelFormat format);

// 最简创建：RGBA8888 格式
static RenderTexture* create(int w, int h);
```

**参数说明**:
- `w`, `h`: 渲染纹理的宽高（单位：点）；
- `format`: 像素格式，仅支持 RGB 和 RGBA 系列（如 `RGBA8888`、`RGB565`）；
- `depthStencilFormat`: 深度模板格式（如 `GL_DEPTH24_STENCIL8`）。

### 5.3 内部结构

```
RenderTexture
  ├── _FBO                 — 帧缓冲对象句柄
  ├── _depthRenderBufffer  — 深度渲染缓冲句柄
  ├── _oldFBO              — 保存之前的 FBO 绑定
  ├── _texture             — 渲染目标纹理
  ├── _textureCopy         — _texture 的副本（用于 Android 前后台切换恢复）
  ├── _sprite              — 显示结果的精灵
  ├── _pixelFormat         — 像素格式
  ├── _keepMatrix          — 是否保持当前矩阵
  ├── _clearFlags          — 自动绘制时的清除标志
  ├── _clearColor          — 自动绘制时的清除颜色
  ├── _clearDepth          — 自动绘制时的清除深度值
  ├── _clearStencil        — 自动绘制时的清除模板值
  └── _autoDraw            — 是否自动绘制到纹理
```

### 5.4 begin/end 渲染流程

```cpp
// 开始捕获（不清除）
virtual void begin();

// 开始捕获并清除（更高效，推荐）
virtual void beginWithClear(float r, float g, float b, float a);
virtual void beginWithClear(float r, float g, float b, float a, float depthValue);
virtual void beginWithClear(float r, float g, float b, float a, float depthValue, int stencilValue);

// 结束捕获
virtual void end();
// Lua 专用别名（end 是 Lua 关键字）
inline void endToLua();
```

**典型渲染流程**:
```
1. beginWithClear()      → 绑定 FBO，设置视口，清除缓冲区
2. node->visit()         → 将目标节点渲染到 FBO 中
3. end()                 → 解绑 FBO，恢复视口
4. 结果纹理可通过 getSprite() 获取并显示
```

### 5.5 清除操作

| 方法 | 说明 |
|------|------|
| `clear(r, g, b, a)` | 清除颜色缓冲 |
| `clearDepth(depthValue)` | 清除深度缓冲 |
| `clearStencil(stencilValue)` | 清除模板缓冲 |

## 6. ParallaxNode — 视差节点

**文件**: `cocos/2d/CCParallaxNode.h`，继承自 `Node`

### 6.1 概述

ParallaxNode 用于模拟视差滚动效果。通过为每个子节点设置不同的视差比率（parallax ratio），当父节点移动时，各子节点以不同速度移动，从而产生深度感（近景快、远景慢）。

### 6.2 视差滚动原理

```
父节点移动距离 = Δx

子节点实际移动距离 = Δx × parallaxRatio.x + positionOffset.x

例如：
  - 远景层 parallaxRatio = (0.2, 0.2) → 移动很慢
  - 中景层 parallaxRatio = (0.5, 0.5) → 移动适中
  - 近景层 parallaxRatio = (1.0, 1.0) → 与父节点同步
```

内部实现：
1. 在 `visit()` 中，计算父节点当前位置与 `_lastPosition` 的差值；
2. 根据每个子节点的 `parallaxRatio` 和 `positionOffset` 计算实际位置；
3. 更新 `_lastPosition`。

### 6.3 接口

```cpp
static ParallaxNode* create();

// 核心方法：添加带视差比率的子节点
void addChild(Node* child, int z, const Point& parallaxRatio, const Point& positionOffset);

// 内部数组管理
void setParallaxArray(_ccArray *parallaxArray);
_ccArray* getParallaxArray();
```

**参数说明**:
- `child`: 子节点；
- `z`: Z 序（用于分层）；
- `parallaxRatio`: 视差比率，`(1.0, 1.0)` 表示与父节点同步移动，`(0.5, 0.5)` 表示半速移动；
- `positionOffset`: 位置偏移量（初始偏移）。

**注意**: ParallaxNode 重写了 `addChild`/`removeChild`/`visit` 等基础方法，不要使用标准的 `addChild(Node*)` 添加子节点，应使用 `addChild(Node*, int, Point, Point)`。

### 6.4 使用示例

```cpp
// 创建视差节点
auto parallax = ParallaxNode::create();
this->addChild(parallax);

// 添加远景层（移动速度慢）
auto farBg = Sprite::create("far_bg.png");
parallax->addChild(farBg, 0, Point(0.2f, 0.2f), Point(0, 0));

// 添加中景层（移动速度适中）
auto midBg = Sprite::create("mid_bg.png");
parallax->addChild(midBg, 1, Point(0.5f, 0.5f), Point(0, 0));

// 添加近景层（移动速度与父节点同步）
auto nearBg = Sprite::create("near_bg.png");
parallax->addChild(nearBg, 2, Point(1.0f, 1.0f), Point(0, 0));

// 通过移动父节点驱动视差效果
auto moveAction = MoveBy::create(5.0f, Point(-200, 0));
parallax->runAction(moveAction);
// farBg 移动 -40, midBg 移动 -100, nearBg 移动 -200
```

## 7. AtlasNode — 图集节点

**文件**: `cocos/2d/CCAtlasNode.h`，继承自 `Node` + `TextureProtocol`

### 7.1 概述

AtlasNode 是基于纹理图集（TextureAtlas）的快速渲染节点，用于高效渲染大量相同尺寸的纹理块。它是 `LabelAtlas`（字符图集标签）的基类，也适用于需要批量渲染固定尺寸纹理块的场景。

### 7.2 架构

```
AtlasNode
  ├── _textureAtlas      — TextureAtlas 对象（管理纹理和四边形）
  ├── _itemWidth         — 每个图集项的宽度
  ├── _itemHeight        — 每个图集项的高度
  ├── _itemsPerRow       — 每行项数
  ├── _itemsPerColumn    — 每列项数
  ├── _quadsToDraw       — 实际绘制的四边形数量
  ├── _blendFunc         — 混合模式
  ├── _colorUnmodified   — 未修改的颜色
  ├── _isOpacityModifyRGB — 不透明度是否影响 RGB
  ├── _ignoreContentScaleFactor — 是否忽略内容缩放因子
  └── _quadCommand       — 四边形渲染命令
```

### 7.3 接口

```cpp
// 创建
static AtlasNode* create(const std::string& filename, int tileWidth, int tileHeight, int itemsToRender);

// 纹理图集
void setTextureAtlas(TextureAtlas* textureAtlas);
TextureAtlas* getTextureAtlas() const;

// 绘制数量
void setQuadsToDraw(ssize_t quadsToDraw);
ssize_t getQuadsToDraw() const;

// 纹理
virtual Texture2D* getTexture() const override;
virtual void setTexture(Texture2D *texture) override;

// 颜色/不透明度
virtual const Color3B& getColor() const override;
virtual void setColor(const Color3B& color) override;
virtual void setOpacity(GLubyte opacity) override;
virtual void setOpacityModifyRGB(bool isOpacityModifyRGB) override;

// 混合
virtual void setBlendFunc(const BlendFunc& blendFunc) override;
virtual const BlendFunc& getBlendFunc() const override;

// 更新图集值（子类重写）
virtual void updateAtlasValues();
```

**参数说明**:
- `filename`: 图集纹理文件路径；
- `tileWidth` / `tileHeight`: 每个图集项的宽高（点）；
- `itemsToRender`: 最多可渲染的项数。

### 7.4 工作原理

1. 创建时根据 `tileWidth`、`tileHeight` 和纹理尺寸自动计算 `_itemsPerRow`、`_itemsPerColumn`；
2. 为每个槽位预分配四边形（Quad）顶点数据；
3. 子类通过重写 `updateAtlasValues()` 更新每个四边形的纹理坐标和顶点位置；
4. 渲染时通过 `QuadCommand` 一次性提交所有四边形。

### 7.5 使用示例

```cpp
// 创建图集节点（8x12字符的字体图集，最多渲染100个字符）
auto atlas = AtlasNode::create("font_atlas.png", 8, 12, 100);
this->addChild(atlas);

// 设置颜色
atlas->setColor(Color3B(255, 200, 100));

// 控制绘制数量
atlas->setQuadsToDraw(50);

// 更常见的用法是使用 LabelAtlas（AtlasNode 的子类）
auto label = LabelAtlas::create("0123456789", "number_font.png", 16, 24, '0');
this->addChild(label);
label->setString("999");
```

## 8. Grid 网格系统

**文件**: `cocos/2d/CCGrid.h`、`cocos/2d/CCNodeGrid.h`

### 8.1 概述

Grid 网格系统用于实现 3D 网格特效（如波浪、翻转、抖动等），是 `ActionGrid` 系列动作的基础。Grid 将目标节点的纹理分割为网格，通过操纵网格顶点实现特效。

### 8.2 类层次结构

```
Ref
└── GridBase                   — 网格基类
    ├── Grid3D                 — 3D 网格（顶点含 Z 坐标）
    └── TiledGrid3D            — 平铺 3D 网格（瓦片可分离）

Node
└── NodeGrid                  — 网格特效容器节点
```

### 8.3 GridBase — 网格基类

```cpp
class GridBase : public Ref {
public:
    static GridBase* create(const Size& gridSize, Texture2D *texture, bool flipped);
    static GridBase* create(const Size& gridSize);

    // 激活状态
    bool isActive() const;
    void setActive(bool active);

    // 重用次数
    int getReuseGrid() const;
    void setReuseGrid(int reuseGrid);

    // 网格尺寸
    const Size& getGridSize() const;
    void setGridSize(const Size& gridSize);

    // 网格间距
    const Point& getStep() const;
    void setStep(const Point& step);

    // 纹理翻转
    bool isTextureFlipped() const;
    void setTextureFlipped(bool flipped);

    // 绘制流程
    void beforeDraw();
    void afterDraw(Node *target);
    virtual void blit();
    virtual void reuse();
    virtual void calculateVertexPoints();

protected:
    bool _active;                    // 是否激活
    int  _reuseGrid;                // 重用次数
    Size _gridSize;                 // 网格尺寸（如 (16,12) 表示 16×12 的网格）
    Texture2D *_texture;            // 目标纹理
    Point _step;                    // 网格间距（像素）
    Grabber *_grabber;              // 纹理抓取器
    bool _isTextureFlipped;         // 纹理是否翻转

```

**核心概念**:
- `gridSize`: 定义网格的列数和行数，如 `(16, 12)` 表示 16 列 × 12 行；
- `_step`: 每个网格单元在纹理中的像素间距，由 `gridSize` 和纹理尺寸自动计算；
- `beforeDraw()` / `afterDraw()`: 在绘制目标节点时抓取纹理并应用网格变形。

### 8.4 Grid3D — 3D 网格

```cpp
class Grid3D : public GridBase {
public:
    static Grid3D* create(const Size& gridSize, Texture2D *texture, bool flipped);
```

**特点**:
- 每个顶点包含 X、Y、Z 三个维度；
- 修改顶点的 Z 值可实现波浪、隆起等 3D 效果；
- 网格顶点之间连续，整体变形。

### 8.5 TiledGrid3D — 平铺 3D 网格

```cpp
class TiledGrid3D : public GridBase {
public:
    static TiledGrid3D* create(const Size& gridSize, Texture2D *texture, bool flipped);
    static TiledGrid3D* create(const Size& gridSize);

    // 获取/设置瓦片

```

**与 Grid3D 的区别**:
- TiledGrid3D 的每个瓦片可以独立移动，瓦片之间可以分离；
- 适合实现破碎、飞散、翻转等瓦片级特效；
- 每个瓦片由 4 个顶点（Quad3）组成。

### 8.6 NodeGrid — 网格特效容器

```cpp
class NodeGrid : public Node {
public:
    static NodeGrid* create();

    GridBase* getGrid();
    void setGrid(GridBase *grid);
    void setTarget(Node *target);

    virtual void visit(Renderer *renderer, const kmMat4 &parentTransform, bool parentTransformUpdated) override;

protected:
    Node* _gridTarget;            // 应用网格特效的目标节点
    GridBase* _nodeGrid;          // 网格对象
    GroupCommand _groupCommand;   // 分组渲染命令
    CustomCommand _gridBeginCommand;
    CustomCommand _gridEndCommand;
};
```

**工作原理**:
1. 将需要特效的节点设置为 `_gridTarget`；
2. 设置对应的 Grid 对象（Grid3D 或 TiledGrid3D）；
3. `visit()` 中：
   - `onGridBeginDraw()`: 抓取目标节点纹理到 Grid；
   - Grid 应用变形；
   - `onGridEndDraw()`: 渲染变形后的网格。

**注意**: 通常不直接使用 NodeGrid，而是通过 `ActionGrid` 系列动作（如 `Waves3D`、`FlipX3D`、`Shaky3D` 等）自动创建和管理。

### 8.8 Grabber — 纹理抓取器

**文件**：`cocos/2d/CCGrabber.h`

`Grabber` 是 Grid 系统内部使用的辅助类，负责通过 FBO（帧缓冲对象）抓取目标节点的渲染纹理。`GridBase` 通过 `_grabber` 成员持有 Grabber 实例，用于 `beforeDraw()` / `afterDraw()` 流程中的纹理抓取和释放。

```cpp
class Grabber : public Ref {
public:
    Grabber();

    // 抓取指定纹理区域到内部 FBO

    void afterRender(Texture2D* texture);
};
```

> **注意**：`Grabber` 是内部实现类，用户通常不直接使用它。它由 `GridBase` 在 `beforeDraw()` 中自动调用 `grab()` 来抓取目标节点纹理。


## 9. 注意事项与最佳实践

### 9.1 DrawNode

- **性能优势**: DrawNode 将所有图元合并为单批次渲染，比 `CCDrawingPrimitives` 快得多，适合大量动态几何绘制；
- **内存管理**: 频繁调用 `clear()` 后重新绘制，避免无限增长缓冲区；
- **颜色格式**: 使用 `Color4F`（浮点颜色），注意与 `Color3B`/`Color4B` 的区别；
- **坐标系统**: 所有绘制坐标均为节点本地坐标，受节点的 position、anchorPoint、scale 等变换影响；
- **限制**: 不支持纹理贴图，绘制结果仅为纯色几何形状。

### 9.2 MotionStreak

- **纹理要求**: 拖尾纹理应为水平方向的 1D 渐变纹理（左端不透明、右端透明），用于实现自然的淡出效果；
- **性能考虑**: `minSeg` 越小、`fade` 越大，顶点数越多，性能开销越大；在移动端应合理设置参数；
- **快速模式**: 对精度要求不高的场景启用 `setFastMode(true)` 可减少 CPU 开销；
- **位置同步**: 拖尾不自动跟随节点，需要每帧手动 `setPosition()` 同步；
- **重置**: 切换场景或重新开始时调用 `reset()` 清除旧拖尾。

### 9.3 ClippingNode

- **模板缓冲限制**: 需要 OpenGL 支持模板缓冲（大多数现代设备支持），模板缓冲位数通常为 8 位；
- **嵌套裁剪**: 多层 ClippingNode 嵌套会消耗多个模板位（`_mask_layer_le`），嵌套深度受模板缓冲位宽限制；
- **模板节点选择**: 模板节点应为简单形状，避免使用复杂纹理或过多子节点；模板节点本身不渲染到颜色缓冲；
- **Alpha 阈值**: 设为 `1.0` 时禁用 Alpha 测试（二进制裁剪），设为 `< 1.0` 可实现柔边效果；
- **性能**: 模板测试会增加 GPU 开销，避免在大量节点上同时使用 ClippingNode；
- **状态恢复**: ClippingNode 会在渲染前后保存和恢复 OpenGL 模板状态，不影响其他节点。

### 9.4 ProgressTimer

- **精灵锚点**: ProgressTimer 的 Sprite 锚点会影响进度展开的视觉效果，特别是 RADIAL 类型；
- **中点坐标**: 归一化坐标 `(0~1, 0~1)`，相对于精灵尺寸；
- **BAR 变化率**: `_barChangeRate` 的 x 和 y 分量通常只有一个非零值，表示变化方向；
- **顶点更新**: 每次 `setPercentage()` 都会重新计算顶点数据，频繁调用时注意性能；
- **与 Action 配合**: 可使用 `ProgressTo`、`ProgressFromTo` 动作实现动画效果。

### 9.5 RenderTexture

- **FBO 完整性**: 创建后应检查 FBO 是否完整（OpenGL 错误检查），部分设备可能不支持特定的像素格式或深度模板格式；
- **像素格式**: 仅支持 RGB 和 RGBA 格式，不支持 Alpha-only 格式；
- **内存占用**: 大尺寸 RenderTexture 消耗大量 GPU 内存，根据实际需求选择合适尺寸；
- **Android 生命周期**: 使用 `listenToBackground()`/`listenToForeground()` 处理 OpenGL 上下文丢失问题；
- **begin/end 配对**: 每次 `begin()` 必须对应一次 `end()`，否则 FBO 绑定状态异常；
- **自动绘制**: `setAutoDraw(true)` 简化了使用，但需正确设置 `_clearFlags` 等清除参数；
- **保存文件**: 保存操作在渲染线程中同步执行，大纹理保存可能阻塞渲染，建议异步处理。

### 9.6 ParallaxNode

- **添加子节点**: 必须使用 `addChild(Node*, int, Point, Point)` 四参数版本，使用标准 `addChild` 会导致未定义行为；
- **视差比率**: 比率小于 1 表示子节点移动比父节点慢（远景），大于 1 表示更快（近景）；
- **位置偏移**: `positionOffset` 用于设置子节点相对于计算位置的初始偏移；
- **移动方式**: 通过移动 ParallaxNode 本身来驱动所有子节点，而不是直接移动子节点。

### 9.7 AtlasNode

- **图集项尺寸**: 所有图集项必须具有相同的 `tileWidth` 和 `tileHeight`；
- **子类使用**: 多数情况下直接使用 `LabelAtlas` 而非 `AtlasNode`；
- **颜色设置**: 修改 `color` 会影响所有图集项的渲染颜色；
- **绘制数量**: 通过 `setQuadsToDraw()` 可控制实际绘制的四边形数量，减少不必要的绘制。

### 9.8 Grid 系统

- **推荐用法**: 通过 `ActionGrid` 系列动作使用网格特效，而非直接操作 Grid 对象；
- **网格尺寸**: 网格越密（`gridSize` 越大），特效越精细，但性能开销越大；
- **纹理抓取**: Grid 会在 `beforeDraw()` 中抓取目标节点纹理，目标节点越大，抓取开销越大；
- **重用**: `_reuseGrid` 控制网格复用次数，减少重复创建；
- **投影**: Grid 内部会切换投影模式，确保 `setGrid()` 后 Director 投影状态正确。
