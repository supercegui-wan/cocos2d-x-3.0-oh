# cocos2d-x 3.0-oh 着色器与组件系统

## 概述

本文档涵盖 cocos2d-x 3.0-oh 中的着色器程序管理、组件系统、调度器和引擎配置等核心模块。这些模块共同构成了引擎的渲染定制能力、节点扩展机制、定时回调基础设施和 GPU 能力查询体系。

**涉及文件**：

| 模块 | 头文件 |
|------|--------|
| GLProgram | `cocos/2d/CCGLProgram.h` |
| ShaderCache | `cocos/2d/CCShaderCache.h` |
| Component | `cocos/2d/CCComponent.h` |
| ComponentContainer | `cocos/2d/CCComponentContainer.h` |
| Scheduler | `cocos/2d/CCScheduler.h` |
| Configuration | `cocos/2d/CCConfiguration.h` |

## 1. GLProgram — 着色器程序

**文件**：`cocos/2d/CCGLProgram.h`

GLProgram 封装了 OpenGL（ES）着色器程序的完整生命周期，继承自 `Ref`，是引擎中自定义渲染效果的核心入口。它管理顶点着色器和片段着色器的编译、链接、属性绑定以及 Uniform 变量设置。

### 1.1 顶点属性（Vertex Attributes）

引擎预定义了三个标准顶点属性槽位，与 `ccVertexAttribFlags` 配合使用：

```cpp
enum {
    VERTEX_ATTRIB_POSITION,   // 顶点位置（对应 a_position）
    VERTEX_ATTRIB_COLOR,      // 顶点颜色（对应 a_color）
    VERTEX_ATTRIB_TEX_COORDS, // 纹理坐标（对应 a_texCoord）

    VERTEX_ATTRIB_MAX,        // 属性槽位总数
};
```

| 属性常量 | 属性名称（GLSL） | 用途 |
|----------|------------------|------|
| `VERTEX_ATTRIB_POSITION` | `a_position` | 顶点位置坐标 |
| `VERTEX_ATTRIB_COLOR` | `a_color` | 顶点颜色 |
| `VERTEX_ATTRIB_TEX_COORDS` | `a_texCoord` | 纹理坐标 |

对应的属性名常量：

```cpp
static const char* ATTRIBUTE_NAME_COLOR;      // "a_color"
static const char* ATTRIBUTE_NAME_POSITION;   // "a_position"
static const char* ATTRIBUTE_NAME_TEX_COORD;  // "a_texCoord"
```

### 1.2 内置 Uniform（Built-in Uniforms）

引擎预定义了 8 个内置 Uniform 槽位，在 `updateUniforms()` 中自动绑定：

```cpp
enum {
    UNIFORM_P_MATRIX,    // 投影矩阵
    UNIFORM_MV_MATRIX,   // 模型视图矩阵
    UNIFORM_MVP_MATRIX,  // 模型视图投影矩阵（复合）
    UNIFORM_TIME,        // 引擎运行时间（秒）
    UNIFORM_SIN_TIME,    // sin(time)
    UNIFORM_COS_TIME,    // cos(time)
    UNIFORM_RANDOM01,    // 0~1 之间的随机浮点数
    UNIFORM_SAMPLER,     // 纹理采样器（绑定到纹理单元 0）

    UNIFORM_MAX,
};
```

对应的 Uniform 名称常量：

```cpp
static const char* UNIFORM_NAME_P_MATRIX;           // "CC_PMatrix"
static const char* UNIFORM_NAME_MV_MATRIX;          // "CC_MVMatrix"
static const char* UNIFORM_NAME_MVP_MATRIX;         // "CC_MVPMatrix"
static const char* UNIFORM_NAME_TIME;               // "CC_Time"
static const char* UNIFORM_NAME_SIN_TIME;           // "CC_SinTime"
static const char* UNIFORM_NAME_COS_TIME;           // "CC_CosTime"
static const char* UNIFORM_NAME_RANDOM01;           // "CC_Random01"
static const char* UNIFORM_NAME_SAMPLER;            // "CC_Texture0"
static const char* UNIFORM_NAME_ALPHA_TEST_VALUE;   // "CC_alpha_value"
```

内置 Uniform 的更新由标志位驱动，避免不必要的 GPU 调用：

```cpp
struct flag_struct {
    unsigned int usesTime   : 1;  // 着色器是否使用 CC_Time
    unsigned int usesMVP    : 1;  // 着色器是否使用 CC_MVPMatrix
    unsigned int usesMV     : 1;  // 着色器是否使用 CC_MVMatrix
    unsigned int usesP      : 1;  // 着色器是否使用 CC_PMatrix
    unsigned int usesRandom : 1;  // 着色器是否使用 CC_Random01
} _flags;
```

引擎在着色器编译时自动扫描源码，检测其中引用的内置 Uniform 名称并设置对应的标志位，从而在运行时仅更新实际使用的 Uniform。

### 1.3 内置着色器（Built-in Shaders）

引擎预置了 14 种标准化着色器，覆盖常用渲染场景，通过静态常量名称引用：

| 着色器名称常量 | 用途 |
|---------------|------|
| `SHADER_NAME_POSITION_TEXTURE_COLOR` | 标准精灵：位置 + 纹理 + 颜色 |
| `SHADER_NAME_POSITION_TEXTURE_COLOR_NO_MVP` | 同上，但不自动更新 MVP 矩阵 |
| `SHADER_NAME_POSITION_TEXTURE_ALPHA_TEST` | 带 Alpha 测试的纹理着色器 |
| `SHADER_NAME_POSITION_TEXTURE_ALPHA_TEST_NO_MV` | 同上，但不自动更新 MV 矩阵 |
| `SHADER_NAME_POSITION_COLOR` | 纯色：位置 + 颜色 |
| `SHADER_NAME_POSITION_COLOR_NO_MVP` | 同上，但不自动更新 MVP 矩阵 |
| `SHADER_NAME_POSITION_TEXTURE` | 纯纹理：位置 + 纹理坐标 |
| `SHADER_NAME_POSITION_TEXTURE_U_COLOR` | 带统一颜色的纹理着色器 |
| `SHADER_NAME_POSITION_TEXTURE_A8_COLOR` | A8 格式纹理 + 颜色 |
| `SHADER_NAME_POSITION_U_COLOR` | 位置 + 统一颜色 |
| `SHADER_NAME_POSITION_LENGTH_TEXTURE_COLOR` | 基于长度的纹理颜色混合 |
| `SHADER_NAME_LABEL_NORMAL` | 普通标签渲染 |
| `SHADER_NAME_LABEL_OUTLINE` | 带描边的标签渲染 |
| `SHADER_NAME_LABEL_DISTANCEFIELD_NORMAL` | 距离场标签（普通） |
| `SHADER_NAME_LABEL_DISTANCEFIELD_GLOW` | 距离场标签（发光） |

### 1.4 Uniform 操作

GLProgram 提供了一套完整的 Uniform 设置 API，所有方法均采用脏检查（dirty-check）机制：仅当值发生变化时才调用 `glUniform*`，减少 GPU 状态切换开销。

#### 位置查询

```cpp
GLint getUniformLocation(const char* name) const;       // 查询 Uniform 位置
GLint getUniformLocationForName(const char* name) const; // 通过名称获取位置（内部缓存）
```

#### 整数类型 Uniform

| 方法 | 对应 GL 调用 |
|------|-------------|
| `setUniformLocationWith1i(loc, i1)` | `glUniform1i` |
| `setUniformLocationWith2i(loc, i1, i2)` | `glUniform2i` |
| `setUniformLocationWith3i(loc, i1, i2, i3)` | `glUniform3i` |
| `setUniformLocationWith4i(loc, i1, i2, i3, i4)` | `glUniform4i` |
| `setUniformLocationWith2iv(loc, ints, count)` | `glUniform2iv` |
| `setUniformLocationWith3iv(loc, ints, count)` | `glUniform3iv` |
| `setUniformLocationWith4iv(loc, ints, count)` | `glUniform4iv` |

#### 浮点类型 Uniform

| 方法 | 对应 GL 调用 |
|------|-------------|
| `setUniformLocationWith1f(loc, f1)` | `glUniform1f` |
| `setUniformLocationWith2f(loc, f1, f2)` | `glUniform2f` |
| `setUniformLocationWith3f(loc, f1, f2, f3)` | `glUniform3f` |
| `setUniformLocationWith4f(loc, f1, f2, f3, f4)` | `glUniform4f` |
| `setUniformLocationWith2fv(loc, floats, count)` | `glUniform2fv` |
| `setUniformLocationWith3fv(loc, floats, count)` | `glUniform3fv` |
| `setUniformLocationWith4fv(loc, floats, count)` | `glUniform4fv` |

#### 矩阵类型 Uniform

| 方法 | 对应 GL 调用 |
|------|-------------|
| `setUniformLocationWithMatrix2fv(loc, mat, count)` | `glUniformMatrix2fv` |
| `setUniformLocationWithMatrix3fv(loc, mat, count)` | `glUniformMatrix3fv` |
| `setUniformLocationWithMatrix4fv(loc, mat, count)` | `glUniformMatrix4fv` |

#### 内置 Uniform 更新

```cpp
void setUniformsForBuiltins();                        // 更新所有内置 Uniform
void setUniformsForBuiltins(const kmMat4 &modelView);  // 更新内置 Uniform，使用指定 MV 矩阵
```

### 1.5 程序生命周期

```
构造函数 GLProgram()
    ↓
初始化（三选一）
├── initWithByteArrays(vShader, fShader)        // 从内存中的字节数组加载
├── initWithFilenames(vShaderFile, fShaderFile)  // 从文件加载
└── initWithPrecompiledProgramByteArray(...)     // 从预编译字节码加载（仅 WP8/WinRT）
    ↓
bindAttribLocation(name, index)   // 绑定属性位置（在 link() 前调用）
    ↓
link()                            // 链接着色器程序
    ↓
use()                             // 激活程序（调用 glUseProgram）
    ↓
updateUniforms()                  // 初始化内置 Uniform 位置
    ↓
setUniformsForBuiltins()          // 每帧更新内置 Uniform 值
    ↓
reset()                           // 重新加载着色器（Android 上下文恢复时使用）
    ↓
析构 ~GLProgram()                 // 释放 OpenGL 资源
```

#### 初始化的三种方式

```cpp
// 方式一：从字节数组（字符串）加载（推荐用于内嵌着色器）
bool initWithByteArrays(const GLchar* vShaderByteArray, const GLchar* fShaderByteArray);

// 方式二：从文件加载（用于外部着色器文件）
bool initWithFilenames(const std::string& vShaderFilename, const std::string& fShaderFilename);

// 方式三：从预编译字节码加载（仅 WP8/WinRT 平台）
bool initWithPrecompiledProgramByteArray(const GLchar* vShaderByteArray, const GLchar* fShaderByteArray);
```

#### 调试方法

```cpp
std::string getVertexShaderLog() const;    // 获取顶点着色器编译日志
std::string getFragmentShaderLog() const;  // 获取片段着色器编译日志
std::string getProgramLog() const;         // 获取程序链接日志
inline const GLuint getProgram() const;    // 获取底层 OpenGL 程序句柄
```

### 1.6 使用示例

```cpp
// 示例 1：从字节数组创建自定义着色器
const GLchar* vertexShader = R"(
    attribute vec4 a_position;
    attribute vec2 a_texCoord;
    varying vec2 v_texCoord;
    void main() {
        gl_Position = CC_MVPMatrix * a_position;
        v_texCoord = a_texCoord;
    }
)";

const GLchar* fragmentShader = R"(
    varying vec2 v_texCoord;
    uniform sampler2D CC_Texture0;
    uniform float u_time;
    void main() {
        vec4 color = texture2D(CC_Texture0, v_texCoord);
        // 使用内置 Uniform 实现灰度效果
        float gray = dot(color.rgb, vec3(0.299, 0.587, 0.114));
        gl_FragColor = vec4(gray, gray, gray, color.a);
    }
)";

auto program = new GLProgram();
program->initWithByteArrays(vertexShader, fragmentShader);
program->bindAttribLocation(GLProgram::ATTRIBUTE_NAME_POSITION, GLProgram::VERTEX_ATTRIB_POSITION);
program->bindAttribLocation(GLProgram::ATTRIBUTE_NAME_TEX_COORD, GLProgram::VERTEX_ATTRIB_TEX_COORDS);
program->link();
program->updateUniforms();

// 设置自定义 Uniform
auto loc = program->getUniformLocation("u_time");
program->setUniformLocationWith1f(loc, 1.5f);

// 应用到精灵
sprite->setGLProgram(program);
sprite->setGLProgramState(GLProgramState::getOrCreateWithGLProgram(program));

// 示例 2：从文件加载着色器
auto program2 = new GLProgram();
program2->initWithFilenames("shaders/myVertexShader.vsh", "shaders/myFragmentShader.fsh");
program2->link();
program2->updateUniforms();

// 示例 3：使用内置着色器
auto sprite = Sprite::create("image.png");
// 自动使用 SHADER_NAME_POSITION_TEXTURE_COLOR
```

## 2. ShaderCache — 着色器缓存

**文件**：`cocos/2d/CCShaderCache.h`

ShaderCache 是 GLProgram 的单例缓存管理器，负责预加载、存储和检索着色器程序，避免重复编译相同的着色器。

### 2.1 类层次与单例管理

```cpp
class ShaderCache : public Ref {
public:
    static ShaderCache* getInstance();       // 获取单例
    static void destroyInstance();           // 销毁单例
    GLProgram* getProgram(const std::string &key);  // 按名称获取着色器
    void addProgram(GLProgram* program, const std::string &key);  // 注册着色器
    // 已废弃的别名
    CC_DEPRECATED_ATTRIBUTE static ShaderCache* sharedShaderCache();
    CC_DEPRECATED_ATTRIBUTE static void purgeSharedShaderCache();
    CC_DEPRECATED_ATTRIBUTE GLProgram* programForKey(const std::string &key);
};
```

### 2.2 缓存策略

ShaderCache 内部使用 `std::unordered_map<std::string, GLProgram*>` 以字符串键名管理所有着色器程序：

```cpp
std::unordered_map<std::string, GLProgram*> _programs;
```

- **键名**：着色器的唯一标识符，如 `"ShaderPositionTextureColor"`
- **值**：已编译链接的 GLProgram 实例
- **生命周期**：缓存中的程序由 ShaderCache 持有引用，直到 `destroyInstance()` 被调用

### 2.3 预加载（loadDefaultShaders）

在引擎初始化时，`loadDefaultShaders()` 会预编译所有 14 种内置着色器并注册到缓存中。该过程在 `Director::init()` 中自动触发。

```cpp
void loadDefaultShaders();     // 首次加载默认着色器
void reloadDefaultShaders();    // 重新加载默认着色器（Android 上下文恢复时）
```

### 2.4 使用示例

```cpp
// 示例 1：获取内置着色器
auto cache = ShaderCache::getInstance();
auto program = cache->getProgram(GLProgram::SHADER_NAME_POSITION_TEXTURE_COLOR);
sprite->setGLProgram(program);

// 示例 2：注册自定义着色器到缓存
auto customProgram = new GLProgram();
customProgram->initWithByteArrays(vertSrc, fragSrc);
customProgram->link();
customProgram->updateUniforms();
cache->addProgram(customProgram, "MyCustomShader");

// 之后任何地方都可以通过名称获取
auto cached = cache->getProgram("MyCustomShader");

// 示例 3：重新加载（Android 上下文恢复）
cache->reloadDefaultShaders();
```

## 3. Component — 组件系统

**文件**：`cocos/2d/CCComponent.h`

Component 是 cocos2d-x 3.0 引入的组件化架构基类，允许将可复用的逻辑模块附加到 Node 上，实现功能组合而非继承扩展。

### 3.1 组件模型

```cpp
class Component : public Ref {
CC_CONSTRUCTOR_ACCESS:
    Component(void);
public:
    virtual ~Component(void);
    virtual bool init();
    static Component* create(void);
};
```

组件继承自 `Ref`，具备引用计数和自动释放能力。通过 `create()` 工厂方法创建，内部调用 `init()`。

### 3.2 组件事件

```cpp
enum {
    kComponentOnEnter,   // 所附着节点 onEnter 时触发
    kComponentOnExit,    // 所附着节点 onExit 时触发
    kComponentOnUpdate   // 所附着节点每帧 update 时触发
};
```

### 3.3 生命周期

```
create()                    // 创建组件实例
    ↓
init()                      // 初始化（可重写）
    ↓
setOwner(node)              // 绑定到节点（由 ComponentContainer 自动调用）
    ↓
onEnter()                   // 节点进入场景（可重写）
    ↓
update(delta)               // 每帧更新（可重写，需节点启用 update）
    ↓
onExit()                    // 节点离开场景（可重写）
    ↓
析构 ~Component()           // 释放资源
```

### 3.4 所有者关系

每个组件必须附着到一个 Node 上：

```cpp
void setOwner(Node *pOwner);   // 设置所有者节点
Node* getOwner() const;        // 获取所有者节点
```

组件通过 `_owner` 成员持有对节点的弱引用，通过 `getOwner()` 可访问节点及其场景上下文。

### 3.5 启用/禁用与名称

```cpp
virtual bool isEnabled() const;                          // 是否启用
virtual void setEnabled(bool b);                         // 设置启用/禁用
const std::string& getName() const;                      // 获取组件名称
void setName(const std::string& name);                   // 设置组件名称
virtual bool serialize(void* r);                         // 序列化（可重写）
```

### 3.6 脚本绑定支持

```cpp
#if CC_ENABLE_SCRIPT_BINDING
ccScriptType _scriptType;  // 脚本类型标记（lua 或 javascript）
#endif
```

### 3.7 成员变量一览

| 成员 | 类型 | 说明 |
|------|------|------|
| `_owner` | `Node*` | 所有者节点 |
| `_name` | `std::string` | 组件名称（用于查找） |
| `_enabled` | `bool` | 启用状态 |
| `_scriptType` | `ccScriptType` | 脚本绑定类型（条件编译） |

### 3.8 使用示例

```cpp
// 示例 1：自定义旋转组件
class RotateComponent : public Component {
public:
    static RotateComponent* create(float speed) {
        auto ret = new RotateComponent();
        if (ret && ret->init()) {
            ret->_speed = speed;
            ret->autorelease();
            return ret;
        }
        CC_SAFE_DELETE(ret);
        return nullptr;
    }

    virtual void update(float delta) override {
        if (_owner) {
            _owner->setRotation(_owner->getRotation() + _speed * delta);
        }
    }

private:
    float _speed;
};

// 使用
auto sprite = Sprite::create("image.png");
auto rotComp = RotateComponent::create(90.0f);  // 每秒旋转 90 度
rotComp->setName("Rotator");
sprite->addComponent(rotComp);
sprite->scheduleUpdate();  // 必须启用 update 才能驱动组件

// 示例 2：生命周期监听组件
class LifecycleLogger : public Component {
public:
    static LifecycleLogger* create() {
        auto ret = new LifecycleLogger();
        if (ret && ret->init()) {
            ret->autorelease();
            return ret;
        }
        CC_SAFE_DELETE(ret);
        return nullptr;
    }

    virtual void onEnter() override {
        CCLOG("Component '%s' onEnter on node: %p", _name.c_str(), _owner);
    }

    virtual void onExit() override {
        CCLOG("Component '%s' onExit on node: %p", _name.c_str(), _owner);
    }
};

// 示例 3：获取和操作组件
auto comp = node->getComponent("Rotator");
if (comp) {
    comp->setEnabled(false);  // 禁用旋转
}
```

## 4. ComponentContainer — 组件容器

**文件**：`cocos/2d/CCComponentContainer.h`

每个 Node 内部持有一个 ComponentContainer 实例，负责管理该节点上所有 Component 的添加、移除、查找和生命周期传播。

### 4.1 类结构

```cpp
class ComponentContainer {
protected:
    ComponentContainer(Node *pNode);   // 构造函数，仅由 Node 调用
public:
    virtual ~ComponentContainer(void);
};
```

ComponentContainer 是 Node 的友元类，构造函数为 `protected`，仅能由 Node 内部创建。

### 4.2 组件管理

```cpp
virtual bool add(Component *com);             // 添加组件
virtual bool remove(const std::string& name);  // 按名称移除组件
virtual void removeAll();                      // 移除所有组件
virtual Component* get(const std::string& name) const;  // 按名称查找组件
bool isEmpty() const;                          // 容器是否为空
```

内部存储结构：

```cpp
Map<std::string, Component*>* _components;   // 组件字典（键为名称）
Node *_owner;                                 // 所有者节点
```

### 4.3 遍历（visit）

```cpp
virtual void visit(float delta);
```

`visit(delta)` 遍历所有已启用的组件，对其调用 `update(delta)`。该方法由 Node 在每帧的 `visit` 流程中自动调用。

### 4.4 使用示例

```cpp
// 示例 1：添加多个组件
auto node = Node::create();
node->addComponent(RotateComponent::create(45.0f));
node->addComponent(LifecycleLogger::create());
node->scheduleUpdate();

// 示例 2：按名称查找和移除
auto rot = node->getComponent("Rotator");
if (rot) {
    node->removeComponent("Rotator");  // 移除旋转组件
}

// 示例 3：清空所有组件
node->removeAllComponents();

// 示例 4：检查组件存在
if (!node->getComponentContainer()->isEmpty()) {
    // 节点上存在组件
}
```

## 5. Scheduler — 调度器

**文件**：`cocos/2d/CCScheduler.h`

Scheduler 是引擎的定时回调管理器，负责所有定时器、每帧更新和延迟回调的调度。每个场景（Scene）持有一个默认 Scheduler，由 Director 驱动。

### 5.1 定时器类型

Scheduler 支持三种回调模式：

#### 5.1.1 Timer 基类

```cpp
class Timer : public Ref {
    float _interval;           // 定时间隔（秒）
    float _elapsed;            // 已流逝时间
    bool _runForever;          // 是否永久运行
    bool _useDelay;            // 是否使用延迟
    unsigned int _timesExecuted; // 已执行次数
    unsigned int _repeat;      // 重复次数（0 = 执行一次）
    float _delay;              // 首次延迟（秒）
};
```

#### 5.1.2 TimerTargetSelector — 选择器回调

```cpp
class TimerTargetSelector : public Timer {
    bool initWithSelector(Scheduler* scheduler, SEL_SCHEDULE selector,
                          Ref* target, float seconds, unsigned int repeat, float delay);
};
```

#### 5.1.3 TimerTargetCallback — Lambda 回调

```cpp
class TimerTargetCallback : public Timer {
    bool initWithCallback(Scheduler* scheduler, const ccSchedulerFunc& callback,
                          void *target, const std::string& key,
                          float seconds, unsigned int repeat, float delay);
};
```

其中 `ccSchedulerFunc` 定义为 `std::function<void(float)>`，支持现代 C++ lambda。

#### 5.1.4 TimerScriptHandler — 脚本回调

```cpp
class TimerScriptHandler : public Timer {
    bool initWithScriptHandler(int handler, float seconds);
};
```

仅在 `CC_ENABLE_SCRIPT_BINDING` 启用时可用。

### 5.2 调度 API

#### 每帧更新（Update）

```cpp
template <class T>
void scheduleUpdate(T *target, int priority, bool paused);
```

每帧调用 `target->update(dt)`。优先级数值越小越早执行。

#### 间隔调度（Lambda）

```cpp
// 完整参数
```

## 7. 注意事项与最佳实践

### 7.1 GLProgram

1. **属性绑定必须在 link() 之前**：`bindAttribLocation()` 必须在调用 `link()` 之前完成，否则绑定无效。
2. **脏检查机制**：所有 `setUniformLocationWith*` 方法内部已实现脏检查，避免对同一个 Uniform 设置相同值时重复调用 `glUniform*`，因此无需在应用层自行缓存。
3. **内置 Uniform 自动更新**：在着色器中使用 `CC_Time`、`CC_MVPMatrix` 等内置名称时，引擎会自动检测并更新，无需手动获取 location 和设置值。
4. **Android 上下文恢复**：Android 平台在应用切换时可能丢失 OpenGL 上下文，需要通过 `reset()` 或 `ShaderCache::reloadDefaultShaders()` 恢复着色器。
5. **着色器编译错误**：使用 `getVertexShaderLog()`、`getFragmentShaderLog()` 和 `getProgramLog()` 排查着色器编译和链接问题。
6. **纹理采样器**：内置 `UNIFORM_SAMPLER` 始终绑定到纹理单元 0，自定义采样器需要手动设置纹理单元索引。

### 7.2 ShaderCache

1. **单例生命周期**：`getInstance()` 在 `Director::init()` 中首次调用，`destroyInstance()` 在 `Director::end()` 时调用，不要在中间手动销毁。
2. **命名冲突**：添加自定义着色器时确保键名不与内置名称冲突。
3. **预加载时机**：如果需要自定义着色器在引擎启动时可用，可在 `AppDelegate::applicationDidFinishLaunching()` 中调用 `ShaderCache::getInstance()->addProgram()` 预先注册。

### 7.3 Component 与 ComponentContainer

1. **Node 必须启用 update**：组件的 `update(delta)` 仅当 Node 调用了 `scheduleUpdate()` 时才会被驱动。
2. **组件名称唯一性**：同一个 Node 上的组件名称应唯一，`add()` 会覆盖同名组件。
3. **owner 生命周期**：组件不要在 `onExit()` 之后访问 `_owner`，此时节点可能已从场景中移除。
4. **序列化**：`serialize()` 是虚函数，可以在子类中实现自定义序列化逻辑。
5. **脚本绑定**：`_scriptType` 仅在 `CC_ENABLE_SCRIPT_BINDING` 宏开启时编译，原生 C++ 代码中不可用。
6. **禁用与启用**：`setEnabled(false)` 后组件将不再接收 `update()` 调用，但 `onEnter()`/`onExit()` 仍然会触发。

### 7.4 Scheduler

1. **优先使用 Lambda**：`TimerTargetCallback`（Lambda 模式）比 `TimerTargetSelector`（选择器模式）更灵活且类型安全。
2. **interval=0 的特殊性**：`interval=0` 表示每帧调用，此时应优先使用 `scheduleUpdate`，性能更优。
3. **时间缩放是全局的**：`setTimeScale()` 影响所有调度器和 Action，不应在需要精确计时的逻辑中使用。
4. **暂停与恢复**：`pauseTarget`/`resumeTarget` 比 `unschedule`/`schedule` 更高效，因为定时器状态保持不变。
5. **线程安全**：`performFunctionInCocosThread()` 是唯一线程安全的调度方法，其他 API 必须在主线程调用。
6. **避免在回调中修改调度**：在定时器回调中 `unschedule` 自身是安全的，但遍历期间修改其他定时器可能导致未定义行为。
7. **target 指针**：`unscheduleAllForTarget()` 使用 `void*` 作为 target，确保传入的指针与调度时一致。

### 7.5 Configuration

1. **初始化顺序**：`gatherGPUInfo()` 在 OpenGL 上下文创建后调用，在此之前查询硬件能力将返回默认值。
2. **纹理格式**：不应假设所有平台支持所有压缩格式，始终使用 `supports*()` 方法进行运行时检测。
3. **扩展字符串**：`checkForGLExtension()` 执行子串匹配，注意避免扩展名冲突（如 `GL_OES_texture` 会匹配 `GL_OES_texture_float`）。
4. **键值存储**：`_valueDict` 是内存中的字典，不会自动持久化。如需持久化配置，使用 `loadConfigFile()` 加载 plist 或 JSON 文件。
5. **NPOT 限制**：虽然 `supportsNPOT()` 返回 true，但 NPOT 纹理在部分设备上可能有性能损失，建议关键纹理仍使用 POT 尺寸。
